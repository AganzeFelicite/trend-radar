Why we did it this way

Order
Data collection first, infrastructure polish later
Momentum is measured against history. If the collector starts late, those days of data are gone for good. Infrastructure can be rebuilt at any time.
Cut
No Terraform before launch
It manages one VPS, a few DNS records and one bucket. Remote state, a plan-on-PR workflow and a rebuild drill would cost 2–3 days. The manual steps get written down instead.
Comes back in P8.1, after launch.
Cut
No Redis
With a single worker, APScheduler's max_instances=1 acts as the job lock. Quota is summed in Postgres, alert dedupe is a unique constraint, and page caching is Next.js revalidate. That's one fewer service to run and secure.
Add it if we ever run more than one worker.
Cut
No dbt, no table partitioning
About 1M signal rows by launch is small for Postgres. A few SQL views cover the aggregations. Both add moving parts without solving a problem we have yet.
dbt when the SQL gets hard to manage; partitioning around 100M rows.
Cut
No login at launch
Nothing sits behind a login until Pro exists. The waitlist is one form, and the admin page uses Caddy's password protection.
Auth.js arrives with Stripe and Pro (P8.3).
Design
Keyword topics first, embeddings only if needed
HDBSCAN gives clusters new labels on every run, so "the same topic keeps the same ID" needs extra matching logic. Keyword topics use a slug as the ID, so they're stable automatically. Embeddings would also add about 2 GB of torch to the image.
Switch if your top-20 review finds too many misses or duplicates.
Design
One Python package at the repo root
The worker and the API share the same database models. One package means one image to build and deploy, and PyCharm detects the .venv automatically.
Security
The YouTube key goes in a header, not the URL
HTTP errors include the request URL. With the key in the URL, it would leak into connector_runs.error and later into Sentry. In the X-Goog-Api-Key header it never shows up.
Correctness
Quota is charged before every attempt, including retries
YouTube bills failed requests too. Counting only successful calls would let us go over the daily limit without noticing.
Correctness
Snapshots are rounded to the hour, with a unique constraint
If a job runs twice in the same hour (a restart or a retry), the second run updates the same row instead of creating a duplicate, so growth rates aren't skewed.
Design
Two searches an hour: newest and most-viewed
"Newest" catches fresh uploads. "Most viewed in the last 24h" catches videos already taking off, which is what a trend radar most needs. Together they use 4,800 of the 10,000 daily units.
Safety
Tests use their own database
The tests wipe and rebuild their tables each run. Pointing them at the real database would erase collected history.
Risk
Keep "GTA" out of the domain
Take-Two is known for takedowns. Using the trademark in the product's own domain is a bigger risk than mentioning it in page content.
